Extended-range charts: from chart tool to game

For chart editor and package builder developers: 7/8-string guitar and 5/6-string bass. The stock formats and string indices stay in place.

Stock, unchanged Stock field used by extended charts New RS7X data Handled in the game by rs7string
1

The tool pipeline

The chart and package identify the instrument. Existing string numbers never shift.

Chart editorFor example, EOF writes arrangement XML: tuning, notes and guitar chord templates with the instrument's extra string indices and frets.
→
ConverterFor example, DLC Builder writes SNG tuning, note indices and section masks. Guitar chords keep stock columns 0–5 and add the extra columns in RS7X.
→
Package builderAdds the appropriate Rs7String tuning keys to manifest JSON and HSAN; puts the SNG, audio and art in a PSARC.
→
Game + rs7stringThe stock loader reads the SNG; rs7string reads its RS7X data and tuning keys and builds the matching instrument.

Choose the instrument

Indices are storage order, not pitch order. Open notes below assume standard tuning.

7-string guitar

Index 6: low B (B1, MIDI 35)

SNG tuning: 7 entries

Manifest / HSAN: Rs7String6

STRS: guitar (0), 7 strings, 1 extended column

8-string guitar

Index 6: low B; index 7: low F# (F#1, MIDI 30)

SNG tuning: 8 entries

Manifest / HSAN: Rs7String6, Rs7String7

STRS: guitar (0), 8 strings, 2 extended columns

5-string bass

Index 4: low B (B0, MIDI 23)

SNG tuning: 6 entries, as stock

Manifest / HSAN: Rs7String4

STRS: bass (1), 5 strings, 0 extended columns

6-string bass

Index 4: low B; index 5: high C (C3, MIDI 48)

SNG tuning: 6 entries, as stock

Manifest / HSAN: Rs7String4, Rs7String5

STRS: bass (1), 6 strings, 0 extended columns

Manifest and HSAN: use the named keys above after string5. Never write a key named string6 or higher: it can crash the stock song list.

The stock loader inflates the whole body, reads the sections up to MetaData and stops. It never checks for leftover bytes, so the block must be inside the zlib stream and the body size must include it.

Arrangement XML to SNG

The proposed XML names continue the stock pattern. This table shows a 7-string guitar example.

Arrangement XMLSNGManifest and HSAN
<tuning string0..5 string6="-2"/> MetaData tuning gets 7 entries (this switches on 7-string mode) "Rs7String6": -2 after string5; never string6
<note string="6" fret="3" .../> stock note record with string = 6; masks and techniques as usual; Sections stringMask bit 6-
<chordTemplate ... fret6 finger6/> Chords columns 0-5 (MIDI notes only for 0-5) + CHDT fret and finger of string 6; dedupe on all 7 columns-
<chord><chordNote string="6" .../></chord> ChordNotes record when any string has a technique or is open + CHNT entry for string 6 (open = mask 0x4)-
<handShape>, <anchor>, phrases, beats, tonesunchanged-

8-string guitar: extend the same pattern with index 7, including string7, fret7 and finger7. Use Rs7String7 in the manifest and HSAN.

5/6-string bass: use indices 4 and 5 in the stock six slots. Bass XML already has tuning fields for these indices, so their presence cannot mark the instrument; the tool writes the matching manifest keys and RS7X marker from its project settings.

5

The RS7X block

Little-endian, no padding. Each section has a 12-byte header (id, u16 version 1, u16 flags with bit 0 = critical, u32 payload size), followed by its payload. The table under the four sections shows what each instrument writes.

Header (16 bytes)
"RS7X"
u16 version       1
u16 headerSize    16
u32 blockSize
u32 sectionCount  3 guitar, 1 bass
STRS (critical, first)
u8 instrument   0 guitar, 1 bass

u8 columnCount  guitar: count - 6
                bass: 0
