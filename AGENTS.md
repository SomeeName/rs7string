# Agent and contributor guide

**Rules and commands for AI coding agents (and humans) working on rs7string.**

[Contributing](CONTRIBUTING.md) · [Development](docs/DEVELOPMENT.md) · [Architecture](docs/ARCHITECTURE.md) · [RS7X spec](docs/release/RS7X-SPEC.md) · [Chart tools](docs/release/CHART-TOOLS.md) · [Releasing](docs/RELEASING.md) · **Agents**

rs7string is a `dinput8.dll` mod that adds seven- and eight-string guitar and five- and six-string bass support to Rocksmith 2014
Remastered (Steam, September 2022 build, 32-bit Windows). It patches the running game at byte-pattern
sites (`sites.json`) with naked stubs and mid-hooks, and ships no Ubisoft data.

Read first: [README.md](README.md), [CONTRIBUTING.md](CONTRIBUTING.md),
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) (build, tools, debug settings) and
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (how the mod works, decisions, known limits).

## Rules

> [!IMPORTANT]
> - **Work only in `SomeeName/rs7string-private`.** The public `SomeeName/rs7string` repository is read-only; never push or make changes there.
> - **Never commit to `main`.** Work on a branch (`fix/...`, `feat/...`, `docs/...`) and open a pull request.
> - Commit messages and author/co-author fields must not contain AI assistant names or attribution.
> - **Do not push, tag or publish a release** unless the maintainer asked for it.
> - **No Ubisoft data:** no encryption keys, game assets (archives, models, textures, movies, sounds),
>   decrypted content, or disassembly/decompiler listings of the game in the repository, issues or
>   pull requests. Short identifiers, addresses, function names and a few bytes of a pattern are fine.
> - **No generated files** from a user's game install: built `.nif` models, asset dumps, patched movies,
>   memory dumps, game logs with personal paths. `.gitignore` excludes the usual output folders.
> - **Never modify a game folder** from a build or test. Back up a file before you replace it there, and never while
>   the game runs.

- Tag findings in developer docs as CONFIRMED (with the address or log line that shows it) or HYPOTHESIS. Player
  docs use neither tag.

## Build and gates

Windows, Visual Studio Build Tools (toolset v145, Win32), PowerShell, [uv](https://docs.astral.sh/uv/).
Commands, flags (`-Asan`, `-Fuzz`, `-SkipAnalysis`), CI and the game-image requirement are owned by
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#build-and-test); the short form:

```powershell
.\build.ps1                                                   # format check, DLL, unit tests, /analyze
uv run pytest tools\tests -q                                  # site table + emulator tests
uv run python tools\sitecheck.py                              # every site resolves in the game image
uv run python tools\check_exports.py bin\Release\dinput8.dll  # exports, image base, imports
```

- A new compiler warning (`/W4 /WX`), `/analyze` finding or layout-baseline growth fails the build: fix it,
  do not disable it. If you run MSBuild yourself, pass `/p:PlatformToolset=v145` and
  `/p:PostBuildEventUseInBuild=false`.
- `build.ps1` fails on unformatted sources: run `.\scripts\format.ps1` first.
- `sitecheck.py` and the emulator tests need your own unpacked game executable and skip without it; say so in
  the pull request. Never commit it.
- Docs-only changes: check that every relative link resolves (`mkdocs build --strict` does, see
  [docs/agents/docs-and-testing.md](docs/agents/docs-and-testing.md)).

Key rules kept here in short: generated headers (`src/generated/`, `*.generated.h`) are regenerated by
`tools/gen_*.py`, never hand-edited; new hooks are C++ mid-hooks, not new `__asm` stubs; no `gs`/`out`/`in`
operand names in inline asm; keep a feature's sites, hooks, settings and tests in `src/features/<name>/`; test
only your own game copy and never post game-derived output.
